# راهنمای توسعه و اتصال ماژول‌های جدید به پلتفرم
### (Guide for Creating and Integrating New Modules)

این راهنما استانداردها و مراحل ساخت، توسعه و انتشار یک ماژول مستقل جدید در معماری ماژولار پلتفرم انبارداری و مالی را تشریح می‌کند.

---

## ۱. ساخت سریع ماژول با اسکریپت خودکار

برای ایجاد ساختار اولیه ماژول جدید بدون دستکاری دستی هسته، از اسکریپت استاندارد زیر در ریشه پروژه استفاده کنید:

```bash
python scripts/new_module.py --code <کد_ماژول> --title-fa "<عنوان فارسی ماژول>"
```

**مثال:**
```bash
python scripts/new_module.py --code logistics --title-fa "سامانه لجستیک و توزیع"
```

این دستور به صورت خودکار:
1. پوشه ماژول بک‌اند را در `warehouse-backend/modules/logistics/` می‌سازد.
2. پوشه ماژول فرانت‌اند را در `warehouse-front/src/app/modules/logistics/` می‌سازد.
3. فایل ثبتی `installed-modules.ts` را در فرانت‌اند به‌روزرسانی می‌کند.
4. اگر پوشه مقصد از قبل وجود داشته باشد، بدون ایجاد تغییر با خطا متوقف می‌شود.

---

## ۲. ساختار پوشه‌ها و فیلدهای قرارداد

### الف) بک‌اند (`warehouse-backend/modules/<code>/`)
```text
warehouse-backend/modules/<code>/
  ├── module.py                 # مانیفست رسمی ماژول بک‌اند
  └── <code>/                   # اپ جنگو ماژول
      ├── __init__.py
      ├── apps.py               # ثبت در رجیستری در متد ready()
      ├── models.py             # مدل‌های داده‌ای ماژول
      ├── urls.py               # اندپوینت‌های API
      ├── migrations/
      │   └── __init__.py
      └── tests.py              # آزمون‌های ماژول
```

**فیلدهای قرارداد `ModuleSpec` در `module.py`:**
- `code`: کد شناسه یکتای ماژول (باید دقیقاً برابر با نام پوشه باشد).
- `title_fa`: نام فارسی رسمی ماژول جهت نمایش در سامانه‌ها.
- `django_apps`: تاپل مسیر کامل کلاس‌های `AppConfig` (مانند `('logistics.apps.LogisticsConfig',)`).
- `api_prefixes`: تاپل پیشوندهای آدرس API تحت مالکیت ماژول (مانند `('api/logistics/',)`).
- `permission_markers`: دسترسی‌های شاخص جهت احراز صلاحیت ماژول.
- `roles`: نقش‌های مجاز ماژول در سیستم.
- `url_includes`: تاپل نگاشت مسیرها به فایل‌های `urls.py`.
- `audit_modules`: نام و عنوان حوزه‌های ممیزی لاگ‌ها.
- `sod_app_module`: شناسه ماژول در تفکیک وظایف رکوردهای حساس.

### ب) فرانت‌اند (`warehouse-front/src/app/modules/<code>/`)
```text
warehouse-front/src/app/modules/<code>/
  ├── module.ts                 # مانیفست رسمی ماژول فرانت‌اند
  ├── <code>.routes.ts          # روت‌های ماژول
  ├── nav-items.ts              # آیتم‌های منوی ناوبری سایدبار
  └── components/               # کامپوننت‌های ماژول
      └── sample-page/
          ├── sample-page.ts
          └── sample-page.html
```

**فیلدهای قرارداد `WhFrontendModule` در `module.ts`:**
- `code`: کد شناسه ماژول (دقیقاً برابر با نام پوشه و مانیفست بک‌اند).
- `titleFa`: عنوان فارسی رسمی.
- `titleShortFa`: عنوان خلاصه جهت نمایش در دکمه‌ها و تگ‌ها.
- `descriptionFa`: توضیحات عملکرد ماژول.
- `icon`: آیکون نمایشی ماژول (اموجی یا کلید معنایی).
- `routePrefix`: پیشوند روت اصلی فرانت‌اند (مانند `/app/logistics`).
- `defaultRoute`: صفحه پیش‌فرض ورود به ماژول.
- `scopeKind`: قلمرو داده‌ای (`warehouse`، `finance`، یا `operations`).
- `permissionMarkers`: کلیدهای دسترسی مورد نیاز جهت فعال‌سازی لانچر و منوها.
- `roles`: نقش‌های کاربری مرتبط.
- `routes`: تابع بارگذاری تنبل روت‌ها (`() => import('./...routes').then(m => m.ROUTES)`).
- `navItems`: منوهای سایدبار شامل `systemNavItems` و `contextNavItems`.
- `extensions`: مشارکت در نقطه‌های توسعه مشترک پلتفرم.

## ۳. جدول نقطه‌های توسعه (Extension Points) و رویدادها

ارتباط ماژول‌ها با هسته صرفاً از طریق رجیستری‌های مشترک و نقاط توسعه انجام می‌شود و هیچ وابستگی مستقیمی بین ماژول‌ها مجاز نیست:

| لایه | نقطه توسعه / رویداد | تابع ثبتی در هسته | کاربرد |
|---|---|---|---|
| **بک‌اند** | حل شرکت مالک رکورد | `contribute('company_of:<kind>', resolver)` | استخراج `company_id` بدون کوئری به ماژول دیگر |
| **بک‌اند** | مدل‌های پشتیبان‌گیری | `contribute('rollback_models', {Name: Model})` | شرکت در اسنپ‌شات‌ها و قابلیت بازگردانی داده |
| **بک‌اند** | موجودیت‌های گزارش‌ساز | `contribute('report_registrars', registrar)` | ثبت مدل‌ها، فیلدها و resolverهای دامنه در موتور گزارش‌ساز |
| **بک‌اند** | دسترسی مشتق شرکت | `register_derived_company_source(func)` | اعطای دسترسی شرکت بر اساس روابط درونی ماژول |
| **بک‌اند** | تنظیمات پیش‌فرض ماژول | `register_settings_defaults(defs, bool_keys)` | ثبت کلیدها و مقادیر اولیه در هسته تنظیمات |
| **بک‌اند** | ماژول‌های لاگ ممیزی | `register_audit_modules(audit_list)` | تفکیک لاگ‌های ممیزی امنیتی بر اساس ماژول |
| **فرانت** | کاشی لانچر برنامه‌ها | `extensions.launcherTile` | افزودن پویای کارت سامانه به صفحه پورتال لانچر (`extraCards`) با تم و شمارش دقیق |
| **فرانت** | میانبرهای منوی کاربری | `extensions.userMenu` | ثبت دسته‌بندی میانبرها (محاسبه پویا از روی داده‌ها) و قلمرو سینک عمیق |
| **فرانت** | ناوبری پوسته اصلی | `extensions.layoutNav` | منوهای اصلی، فرعی و نقش‌ها در سایدبار (حل پویا با `routePrefix`، بخش «سامانه‌های دیگر» و پرچم `hasCompanyDocumentsArchive`) |
| **فرانت** | مرکز عملیات پلتفرم | `extensions.operations` | پیوند سریع در نوار کناری عملیات (`quickLink`)، ویجت انقضای مدارک و پایش همگام‌سازی |
| **فرانت** | پرچم‌های مدیریت شرکت‌ها | `extensions.companies` | فعال‌سازی انبارداری (`hasWarehouseModuleToggle`) و پرچم خزانه‌داری (`providesTreasury`) که تب‌ها و APIهای مالی شرکت را باز می‌کند |
| **فرانت** | نشانی API شرکت‌ها | `extensions.companyApiEndpoints` | نشانی اختصاصی فهرست شرکت‌ها و دسترسی‌ها (`companiesEndpoint`، `accessEndpoint`) |
| **فرانت** | گروه‌های دسترسی کاربر | `extensions.users` | پیش‌تنظیم‌ها و گروه‌های دسترسی ماژول در فرم کاربران (`permissionGroupKeys`) |
| **فرانت** | پایش سلامت سیستم | `extensions.healthDashboard` | شاخص‌ها و پنل‌های سلامت و اتصال ماژول (`panelScopes`) |
| **فرانت** | لاگ‌های ممیزی | `extensions.audit` | قلمروهای لاگ ممیزی در سامانه (`appScopes`) |
| **فرانت** | کارت‌های پرسنلی | `extensions.idCards` | فعال‌سازی چاپ کارت شناسایی و پرسنلی (`supported`) |
| **فرانت** | فیلتر بین‌ماژولی | `extensions.crossModuleFilters` | فیلتر قلمرو بین‌ماژولی نظیر انبار در دیسکت‌ها و حقوق (`warehouseScopeFilter`) |
| **فرانت** | بارگذار تنبل طراح لیبل | `extensions.loadLabelDesigner` | بارگذاری تنبل طراح لیبل بدون افزایش حجم باندل اولیه |

## ۴. قاعدهٔ وابستگی و ایزولاسیون مرزها (Dependency Rules)

1. **فقط هسته:** ماژول‌ها تنها مجاز به ایمپورت از بسته‌های هسته (`core` در بک‌اند و `core/`، `shared/`، `modules/common/` در فرانت‌اند) هستند.
2. **عدم وابستگی متقابل:** هیچ ماژولی هرگز نباید ماژول دیگری را مستقیم ایمپورت کند (`C2 Forbidden Contract`).
3. **پاکی هسته:** هسته سیستم هرگز نام یا مسیر هیچ ماژولی را به صورت مستقیم و سخت‌کدشده نمی‌شناسد (`C3 Forbidden Contract`)؛ کلیه اتصالات به صورت پویا و از طریق رجیستری صورت می‌گیرد.
4. **ایزولاسیون مایگریشن‌ها:** فایل‌های مایگریشن ماژول (`migrations/0001_initial.py`) فقط و فقط می‌توانند به مایگریشن‌های اپ‌های هسته (`accounts`، `companies`، `common`) وابستگی (`dependencies`) داشته باشند و هرگز نباید به مایگریشن‌های ماژول‌های دیگر وابسته شوند.

## ۵. استقرار و پیکربندی پروفایل‌ها

پلتفرم امکان استقرار گزینشی ماژول‌ها را با متغیر محیطی `WH_MODULES` فراهم می‌کند:

- **تنظیم در محیط اجرا یا سرور:**
  ```bash
  # فعال‌سازی ماژول جدید در کنار سایر ماژول‌ها
  WH_MODULES=warehouse,accounting,logistics
  
  # فعال‌سازی انحصاری ماژول جدید برای تست مستقل
  WH_MODULES=logistics
  
  # فعال‌سازی تمامی ماژول‌های کشف‌شده (پیش‌فرض)
  WH_MODULES=all
  ```
- **استقرار با اسکریپت `deploy.ps1`:**
  ```powershell
  # افزودن ماژول به سرور هدف بدون دستکاری سایر سرویس‌ها
  .\deploy.ps1 -Target soft -AddModule logistics
  ```

## ۶. راستی‌آزمایی و دروازه‌های کیفی (Guardians & Verification)

پیش از انتشار و کامیت هر ماژول جدید، دستورهای بررسی کیفیت باید با موفقیت پاس شوند:

1. **بررسی حصار معماری بک‌اند (نگهبان ۲۹):**
   ```bash
   python scripts/e2e/guardian_modularization.py
   ```
   *توضیح:* نگهبان ۲۹ به صورت خودکار پکیج‌های ماژول جدید را کشف کرده و قواعد استقلال و لایه‌بندی را راستی‌آزمایی می‌کند.
2. **بررسی حصار مرزهای فرانت‌اند (نگهبان ۵۷):**
   ```bash
   python scripts/e2e/guardian_57_front_module_fence.py
   ```
   *توضیح:* بررسی می‌کند هیچ ایمپورت غیرمجازی از ماژول جدید به هسته یا سایر ماژول‌ها نشت نکرده باشد و قراردادهای `module.ts` برقرار باشند.
3. **بررسی صحت اپلیکیشن‌های جنگو:**
   ```bash
   python warehouse-backend/manage.py check
   ```
4. **بررسی بیلد مستقل فرانت‌اند:**
   ```bash
   npm --prefix warehouse-front run build:modules
   ```
